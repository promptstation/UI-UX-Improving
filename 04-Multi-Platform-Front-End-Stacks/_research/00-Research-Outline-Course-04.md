**Section 1: Stack Cartography — Mapping 22 Ecosystems**

**Summary:** Surveying web, desktop, and mobile stacks by language, runtime, rendering model, and distribution, building a decision matrix for choosing stacks per product need.

**Absorbed Skill:** Map stacks by architecture and fit; build selection matrices; justify stack choices with evidence.

**Section 2: React Ecosystem — Next.js and shadcn/ui**

**Summary:** Next.js routing and rendering modes, server components discipline, shadcn/ui theming and composition, and production hardening for React delivery.

**Absorbed Skill:** Ship Next.js apps with correct rendering choices; theme and compose shadcn/ui; harden for production.

**Section 3: Vue Ecosystem — Nuxt and Nuxt UI**

**Summary:** Nuxt architecture and modules, composable state patterns, Nuxt UI theming, and maintaining feature parity with React implementations.

**Absorbed Skill:** Ship Nuxt apps idiomatically; manage state with composables; hold parity with sibling stacks.

**Section 4: Desktop Frameworks — JavaFX, Avalonia and WinUI 3**

**Summary:** XAML and FXML UI models, MVVM patterns, native packaging and auto-update per OS, and desktop-specific UX such as menus and windowing.

**Absorbed Skill:** Build native-feel desktop apps in each framework; package and update per OS; respect desktop UX conventions.

**Section 5: Mobile Toolkits — SwiftUI and Jetpack Compose**

**Summary:** Declarative mobile UI on both platforms: state, navigation, lists, and platform services, plus store-readiness requirements.

**Absorbed Skill:** Build equivalent features in SwiftUI and Compose; handle platform services; prepare store submissions.

**Section 6: Parity Engineering — Same Design Across Stacks**

**Summary:** Spec-driven multi-stack builds, shared design tokens, screenshot-diff testing, and change-propagation workflows keeping implementations aligned.

**Absorbed Skill:** Drive multiple stacks from one spec; enforce parity with visual tests; propagate changes cleanly.

**Section 7: Adapter Patterns — Shared Logic, Native Shells**

**Summary:** Sharing API clients, validation, and business rules across stacks via codegen and packages while keeping shells idiomatically native.

**Absorbed Skill:** Share logic via generated clients and packages; keep each shell idiomatic; version shared contracts.

**Section 8: Capstone — One Product, Four Stacks**

**Summary:** Full capstone: one product brief shipped on web, desktop, and both mobile platforms with proven visual and behavioral parity.

**Absorbed Skill:** Deliver one product across four stacks; evidence parity with tests; document stack-specific decisions.
