**Section 1: Token Foundations — Color, Type and Space as Data**

**Summary:** Token tiers from primitive to semantic to component, naming conventions, multi-format export, and single-source-of-truth governance.

**Absorbed Skill:** Architect tiered token systems; name tokens for scale; export to every target format.

**Section 2: Category Palettes — Product-Driven Color Logic**

**Summary:** Palettes bound to product categories: semantic roles, contrast-paired ramps, dark-mode derivation, and rules preventing off-palette drift.

**Absorbed Skill:** Build category-bound palettes; guarantee contrast pairs; derive dark modes systematically.

**Section 3: Typography Systems — Google Fonts Pairings at Scale**

**Summary:** Pairing rules for display and text faces, modular scales, Google Fonts API loading strategy, and fallbacks preserving layout.

**Absorbed Skill:** Pair faces by rule not taste; implement performant font loading; protect layouts with fallbacks.

**Section 4: Component Logic — Variants, States and Slots**

**Summary:** Component APIs as logic: variant matrices, state machines for interactive states, slot composition, and prop contracts across frameworks.

**Absorbed Skill:** Specify variant and state logic; design composable slot APIs; keep contracts consistent.

**Section 5: Landing Patterns — Structural Page Architectures**

**Summary:** Reusable landing structures: hero, proof, feature, pricing, and footer patterns with conversion rationale and responsive rules.

**Absorbed Skill:** Compose landings from proven patterns; justify structures by conversion logic; hold responsiveness.

**Section 6: Theming and Overrides — Master Plus Variants**

**Summary:** Master themes with scoped overrides: brand variants, seasonal skins, and per-surface exceptions without forking the system.

**Absorbed Skill:** Theme via master-plus-overrides; scope exceptions safely; avoid system forks.

**Section 7: Governance — Versioning and Adoption**

**Summary:** Changesets for design tokens, deprecation policy, documentation as contract, and lint rules enforcing system usage.

**Absorbed Skill:** Version and deprecate safely; document as contract; enforce adoption with linting.

**Section 8: Capstone — Shipped Tokenized Design System**

**Summary:** Full capstone: tokens to components to landing pages, versioned, documented, and adopted by a real consuming project.

**Absorbed Skill:** Ship complete tokenized systems; prove adoption; govern evolution professionally.
